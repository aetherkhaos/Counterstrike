## Tasks

### 1. Fork L4.3a

1. Open `L4.3a-[YourLastName]`.
2. Workflow menu → **Duplicate**.
3. Rename the copy `L4.3b-Reinforced-[YourLastName]`.
4. Confirm the original still exists. Work only in the copy.

### 2. CTI Continue On Fail

Apply this to both CTI HTTP nodes: `Query CTI Database` and `API Call for each IP detected`.

1. Open the node → **Settings**.
2. Enable **Continue On Fail** / **Continue (using error output)**.
3. On the error output, add **Edit Fields (Set)** named `Set Intel Status`:
   - `intel_unavailable` = `true` (boolean)
   - `intel_raw` = expression `{{$json.error || 'unknown'}}`
4. On the success output, add **Set** with `intel_unavailable` = `false`.
5. **Merge** success and error before any AI node so downstream items share that field.

### 3. Branch A: timeout and JSON retry (local primary)

Keep `AI Triage Agent` on the local **primary** LiteLLM alias.

1. Open the OpenAI Chat Model / chain settings. Set **Timeout** to `60000` ms (raise if the queue is slow).
2. Enable **Continue On Fail** on `AI Triage Agent` and on `Parse AI Output`.
3. Add **Set** `Set Retry Count` before the agent if missing. Number field `retry_count`, default `0`.
4. On parse or agent failure:
   - **If** `retry_count` `<` `2`: increment `retry_count`, append to the user prompt: `Your previous output was invalid JSON. Return only the JSON object.` Loop back to `AI Triage Agent`.
   - Else **Set** `Set AI Error` and stop retrying:

     ```json
     { "classification": "ERROR", "confidence": 0, "summary": "Two consecutive invalid AI outputs; see raw_ai_output field for forensic." }
     ```

Do not build an unbounded loop. Cap at two retries.

### 4. Branch B: cloud frontier cross-check

1. Duplicate `AI Triage Agent` → `AI Triage Agent (Frontier)`.
2. Reuse the LiteLLM OpenAI credential (`https://litellm.<team-domain>/v1`). Change **Model** to the instructor-published **cloud frontier** id. Do not point at vLLM.
3. Replace the system prompt (same JSON schema, different strategy):

   ```text
   You are a senior security analyst. Given the evidence:
   1. List three possible classifications (Malicious, Suspicious, Benign).
   2. For each, give confidence 0-100 and a one-sentence rationale.
   3. Select the highest-confidence classification and output ONLY:
      {"classification": "...", "confidence": NN, "summary": "..."}
   No markdown.
   ```

4. Duplicate `Parse AI Output` for the frontier branch (or parse each branch before merge).
5. **Merge** both parsed objects. Combine → By Position.
6. Add **Code** `Compare Branches`:

   ```javascript
   const a = $input.all()[0].json;
   const b = $input.all()[1].json;
   const agree = a.classification === b.classification;
   return {
     primary: a,
     secondary: b,
     branch_classifications: [a.classification, b.classification],
     needs_human_review: !agree
   };
   ```

7. Keep `Is Threat Malicious?`. Feed it Branch A `classification` and `confidence`. Do not delete the IF node.

### 5. Structured output

Add **Code** `Format Structured Output` after compare (and after the IF True path, or merge IF results into this node — final item must match this shape):

```javascript
const x = $input.item.json;
const now = new Date().toISOString();
return {
  type: "indicator",
  id: `indicator--${crypto.randomUUID()}`,
  created: now,
  pattern_type: "stix",
  indicator_types: [x.primary.classification.toLowerCase()],
  confidence: x.primary.confidence,
  description: x.primary.summary,
  extensions: {
    cs_ops_week4: {
      intel_unavailable: $('Set Intel Status').item.json.intel_unavailable || false,
      needs_human_review: x.needs_human_review,
      branch_classifications: x.branch_classifications,
      source_artifact: $('Read Syslog File').item.json.fileName || 'unknown'
    }
  }
};
```

Adjust `$('...')` names if yours differ. `confidence` must be a number. Shape is enough; full STIX validity is not required.
