# L4.0.a Alternative Assessment Rubric

**Lab:** L4.0.a Alternative — Reconstruct the Adversary Exfil Receiver and Rehearse SOM  
**Use:** Instructor scoring of reconstruction products and rehearsal evidence  
**Points:** Poor = 1, Marginal = 2, Acceptable = 3, Exemplary = 4 per row  
**Crosswalk:** Row IDs map to grading checkpoints in [L4.0.a Alternative Instructor Setup Guide.md](L4.0.a%20Alternative%20Instructor%20Setup%20Guide.md)

Student-facing note: performance descriptors only — no hidden solution content.

| Instructor question | Poor (1 pt) | Marginal (2 pts) | Acceptable (3 pts) | Exemplary (4 pts) |
| --- | --- | --- | --- | --- |
| **ES-1 (Weight: evidence use). Did the student tie each kept OE element to Week 1 / Week 3 artifacts they already collected?** | Build choices have no cited sources, or rely on instructor-fed destination details. Score: 1 | Some citations, but product/auth/path choices are generic or unlinked to recovered artifacts. Score: 2 | Decision record cites recovered artifacts for the load-bearing receive-path choices and names remaining gaps. Score: 3 | Citations are specific (artifact + what it implied); gaps have defensible substitutes that were actually tested. Score: 4 |
| **ES-2 (Weight: OE selection). Did the keep/cut list show a lean receiver slice instead of a full-range recreation?** | No cut list, or vanity hosts with no plan link (full victim enterprise, extra C2, unused identity). Score: 1 | Cut list exists but kept elements are not tied to whether the recovered client can land a file. Score: 2 | Keep/cut list is plan-linked; unused victim/C2 pieces are cut or explicitly justified. Score: 3 | Selection clearly maps CG/CV / SOM steps to each kept host/service and would help another operator scope the same rebuild. Score: 4 |
| **ES-3 (Weight: path fidelity). Did rehearsal use the recovered client contract rather than a shortcut file drop?** | Success claimed from console copy, admin UI attach, or other non-client placement. Score: 1 | Mixed methods; client path attempted but graded “success” is the shortcut. Score: 2 | Graded rehearsal is a recovered-client (or inspected derived) upload into the student-built receiver. Score: 3 | Client path is exclusive for the SOM claim; any shortcut is labeled out-of-scope and not used as proof. Score: 4 |
| **ES-4 (Weight: destination retarget). Did the student retarget recovered original-range destinations into their assigned block?** | Client still aimed at original-range addressing, or retarget not documented. Score: 1 | Host changed but other recovered destination identity fields left unexplained when they failed. Score: 2 | AAR documents host retarget into the assigned `/29` and why unchanged original destinations could not be used. Score: 3 | Retarget notes cover host plus instance-specific identity fields, with failed-then-fixed evidence. Score: 4 |
| **ES-5 (Weight: auth and upload contract). Did the student reconstruct authentication and upload fields that match the recovered client?** | Auth/upload shape ignored (wrong method, missing fields, password-only path claimed as the malware path). Score: 1 | Partial contract (some headers or fields); failures not diagnosed. Score: 2 | Working match to recovered method, auth material, destination identity, and file+message fields on **this** instance. Score: 3 | Contract match plus a recorded mismatch test that shows why original-instance secrets fail on a new build. Score: 4 |
| **ES-6 (Weight: successful land). Did the student prove a file arrived on the receiver they built?** | No land evidence, or evidence from the original range rather than this OE. Score: 1 | Claim of success without observable receiver-side artifact (UI, API result, or datastore). Score: 2 | At least one successful land with receiver-side evidence recorded. Score: 3 | Land evidence is reproducible (command + expected success cue + where the object is visible) and timestamp-correlatable. Score: 4 |
| **ES-7 (Weight: journal). Did the install/configuration journal make the build repeatable and evidence-driven?** | No journal, or a generic vendor tutorial unrelated to recovered clues. Score: 1 | Steps listed but order/rationale missing; another operator could not repeat them. Score: 2 | Ordered journal sufficient to rebuild the kept stack from staged media, with evidence notes on key choices. Score: 3 | Journal is concise, ordered, and flags decision points (runtime, listen behavior, identity generation) another operator would need. Score: 4 |
| **ES-8 (Weight: friction and envelope). Did rehearsal include a predicted failure and a limits/bounds test?** | Happy-path only; no friction and no bounds. Score: 1 | One of friction or bounds present but thin or unrecorded. Score: 2 | At least one friction inject and one bounds test with predicted vs observed. Score: 3 | Tests isolate load-bearing variables (auth, listen, payload, or build assumption) and clearly mark break points. Score: 4 |
| **ES-9 (Weight: budget and addressing). Did powered-on RAM and static addressing stay inside published constraints?** | Over 50 GB concurrent, or static hosts in the DHCP half / wrong block. Score: 1 | Table present but incomplete; minor addressing mistakes corrected only after prompt. Score: 2 | Host/RAM table ≤ ~50 GB; all static hosts in the assigned upper-half `/29`. Score: 3 | Lean sizing with unused guests powered off; addressing diagram matches the live table exactly. Score: 4 |
| **ES-10 (Weight: snapshots). Did the student record a usable pre-rehearsal restore point?** | No snapshot plan or no snapshot exists. Score: 1 | Snapshot taken but unnamed/unpurposed. Score: 2 | At least one named pre-rehearsal snapshot with a stated purpose. Score: 3 | Snapshot plan covers pre-rehearsal and post-bounds restore so a peer could roll back safely. Score: 4 |
| **ES-11 (Weight: compromises and plan delta). Did the AAR bound the result and change the plan?** | No AAR, or green result treated as universal proof. Score: 1 | Compromises listed generically; no plan change. Score: 2 | AAR states approximations, how they bound claims, and at least one SOM / TTP / prerequisite delta. Score: 3 | Compromises would prevent a reader from over-reading the result; deltas are specific and usable on the next pass. Score: 4 |
| **ES-12 (Weight: doctrine and MITRE pairing). Did the product use SOM/CG/CV language together with ATT&CK tags?** | Neither doctrine terms nor technique tags on rehearsed TTPs. Score: 1 | One lexicon only, or tags unrelated to the receive/exfil path. Score: 2 | Doctrine terms and ATT&CK tags appear together on the rehearsal product. Score: 3 | Pairing is accurate for the rehearsed path and includes partner-facing D3FEND/ENGAGE labels on observed friction. Score: 4 |

## Scoring Notes

- Score the **reconstruction and rehearsal product**, not whether the student used one vendor install method.
- If environment breakage (ISO/share down, pool exhausted) blocked a land, do not penalize ES-6 for that interval; resume after restore.
- Incomplete Week 1/3 notes are not an automatic Poor on ES-1 if the student documented the gap, re-collected from access they already hold, or tested a labeled substitute (Exemplary/Acceptable depends on rigor).
- Instructor-provided destination product, credentials, or API details used as the build spec → cap ES-1 at Poor.
- Shortcut file placement used as the SOM claim → cap ES-3 at Poor even if the stack is otherwise well built.
