# Effects Group Assessment — Instructor Guide

## Objective and context

Culminating effects assessment. Teams plan, rehearse, execute, assess, and report a mission-relevant effect from authorized redirector access while monitoring for OPERATION SHINY HAMMER leakage. Grade with [`rubric.md`](./rubric.md), including automatic-fail and major-penalty gates. Expected products and grading checkpoints live in [`answer-key.md`](./answer-key.md).

## Dual opening

### Option 1 (Interactive / Whiteboard / Kinesthetic)

- **Say:** "You already have authorized redirector access. The commander wants a measurable effect **and** SHINY HAMMER protection. Keyword-only search is not enough. Do not execute until the pre-execution check is approved."
- **Do:** Confirm each team has redirector access details. Post gates: no out-of-scope destruction, no fabricated evidence, alert on confirmed protected data.
- **Ask (Q):** What two things must be true before anyone executes?
- **Expected Response (A):** A rehearsal that tested the sequence, and instructor-as-commander approval of the written pre-execution check.

### Option 2 (Digital Slide / Virtual / Slide Deck)

- **Say:** "You already have authorized redirector access. The commander wants a measurable effect **and** SHINY HAMMER protection. Keyword-only search is not enough. Do not execute until the pre-execution check is approved."
- **Show:** Student-brief commander intent, pre-execution check block, and timeline.
- **Do:** Confirm range access and the alert path for SHINY HAMMER hits.
- **Ask (Q):** What two things must be true before anyone executes?
- **Expected Response (A):** A rehearsal that tested the sequence, and instructor-as-commander approval of the written pre-execution check.

## Instructor resources and pre-class preparation

1. Confirm teams have prior Block 1/3 products plus redirector access (range card or instructor-issued).
2. Prepare [`rubric.md`](./rubric.md) and the student brief.
3. Publish the commander alert path for SHINY HAMMER hits.
4. Assign teams of four. Set visible time boxes for the three phases and both brief windows.
5. Brief automatic-fail and major-penalty gates before Phase 1 work.

## Student resources and environment

- Student brief (issued mission/intent plus OPERATION SHINY HAMMER protected-operation background)
- Prior planning packet / on-target access notes
- Authorized redirector access only
- No extra kit beyond the assigned range

## Facilitation flow

### Step 1: In-brief and team formation (15 min)

- **Say:** Read the issued **mission** (disrupt IOT deny/degrade freedom of maneuver) and **commander’s intent** (purpose, key tasks, end state). Protect SHINY HAMMER. Keyword-only search is not enough. Do not execute until the pre-execution check is approved.
- **Show:** Issued mission and intent, then the SHINY HAMMER protected-operation background. Three-phase structure (plan / rehearse / execute-assess).
- **Do:** Form teams. Confirm access. Repeat go/no-go.
- **Ask (Q):** Why is keyword-only monitoring a major penalty?
- **Expected Response (A):** The adversary may paraphrase or talk around the operation; contextual detection is required.

### Step 2: Phase 1 planning (150 min)

- **Say:** "Update tactical analysis from prior blocks. Name the effect. Write SOM, FSP, tasks, BDA, and the SHINY HAMMER monitoring plan."
- **Show:** Phase 1 deliverable list. Effect vocabulary: deny, degrade, disrupt, deceive, manipulate, reconnoiter, handoff.
- **Do:** Circulate. Stop teams that start live effects. Push CG/CV linkage and rollback.
- **Ask (Q):** What must each option statement include besides the effect name?
- **Expected Response (A):** Relevance to CG/CV, expected adversary response, burn risk, authority, and how BDA will prove it.

### Step 3: Phase 1 briefs (50 min)

- **Say:** "Ten minutes. Convince the commander the effect is feasible, authorized, measurable, and compatible with SHINY HAMMER protection."
- **Show:** EF-1/EF-2 rubric rows.
- **Do:** Feedback on gaps before rehearsal. Do not approve execution yet.
- **Ask (Q):** Where will you monitor, and how will you detect a paraphrase?
- **Expected Response (A):** Named staging/log/queue locations plus a semantic/contextual method — not only `SHINY HAMMER`.

### Step 4: Phase 2 rehearsal and pre-execution check (90 min)

- **Say:** "Rehearse the actual sequence: access, abort, BDA collection, alerting drill. Then fill the written check. Do not execute until I approve it."
- **Show:** Pre-execution check block from the student brief.
- **Do:** Approve, send back, or withhold. Execution before approval is a major penalty.
- **Ask (Q):** What must the rehearsal reveal before go?
- **Expected Response (A):** Timing, access, communication, evidence, rollback, and SHINY HAMMER coverage problems.

### Step 5: Phase 3 execute, monitor, assess, and report (150 min)

- **Say:** "Execute only the approved effect. Maintain presence. If you confirm SHINY HAMMER data: metadata, delete, alert immediately."
- **Show:** Final packet list (depiction, evidence, BDA, monitoring log, five-line effect report).
- **Do:** Watch gates. Collect packets. Run execution briefs and hot wash.
- **Ask (Q):** How do MoP and MoE differ in your BDA?
- **Expected Response (A):** MoP is whether tasks completed; MoE is what changed in adversary capability, behavior, data flow, or access.

## Timing

- 0800–0815 — In-brief
- 0815–1045 — Phase 1 work
- 1045–1135 — Phase 1 briefs
- 1135–1230 — Feedback / lunch
- 1230–1400 — Phase 2 rehearsal and pre-execution check
- 1400–1530 — Phase 3 execution, monitoring, BDA
- 1530–1630 — Final briefs
- 1630–1700 — Hot wash / collection

## Common stalls

- Execution before approval
- Keyword-only monitoring
- Effect disconnected from CG/CV
- BDA that only reports tasks completed
- Broad deletion without metadata
- Preventable loss of redirector access

## Lesson summary

This assessment is plan → rehearse → execute/assess, with protected-information handling scored separately from the primary effect.

## Questions and check on learning

- **Ask (Q):** What is an automatic fail?
- **Expected Response (A):** Out-of-scope destruction, fabricated evidence, or confirmed SHINY HAMMER data with no commander alert.
- **Ask (Q):** What goes in the five-line effect report?
- **Expected Response (A):** Effect, action, predicted response, observed result, burn-risk/BDA reassessment.
