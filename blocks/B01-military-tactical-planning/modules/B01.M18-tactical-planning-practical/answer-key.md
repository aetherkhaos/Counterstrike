# Tactical Planning Practical — Instructor Answer Key

## Objective and starting context

Student teams plan against the Varensk intrusion on the defended Lunovian government network. There is no live target. Source: the parked instructor key in `archive/provenance/answer-key.md`, aligned to the current student brief. The FSB Center 18 chain is the worked example they must not copy.

## Expected product

Mission analysis, SALUTE, DRAW-D, friendly and enemy OCOKA-W, an EMLCOA, a center of gravity and critical vulnerability, RFIs, and an evidence table ready for ATT&CK. A two-minute commander back-brief.

Mission line: deny or degrade the Varenskian actor's ability to collect intelligence from the defended Lunovian government network in order to preserve friendly freedom of maneuver and generate options for pursuit.

## Acceptable answers

- Actor: Varensk ISB Unit 18 Amber Tide, caveated, is strong. A Varensk near-abroad element is acceptable. A generic APT is weak.
- Enemy mission: collect energy, transportation, and border-security policy material. Destructive attack is not supported.
- Current activity: script execution from user paths, outbound web traffic, a removable-media alert, staged office-document archives on a file server, two workstations and one file server.
- Actions on contact: shift infrastructure, reattempt access, add script payloads, or speed collection. Full withdrawal is the weaker default.
- Centers of gravity that earn credit: collection tempo; rapid document discovery plus an outbound path; repeated user-context access to policy workstations and shared stores.
- Critical vulnerabilities that earn credit: script execution and user-writable staging that defenders can watch; a small set of policy users; ordinary outbound web paths that correlate with host events.
- ATT&CK handoff rows ask questions. They do not jump to D3FEND. Script execution asks which interpreter. Outbound web asks whether timing matches staging. Removable media asks whether anything executed. Staged archives ask who created them.

## Grading checkpoints

- Accept: evidence, assumptions, and RFIs kept distinct, and a back-brief a commander can use.
- Do not accept: "block the address" or an ENGAGE option before the evidence table, a domain controller named as key terrain by habit, or the FSB worked example with the names swapped.
