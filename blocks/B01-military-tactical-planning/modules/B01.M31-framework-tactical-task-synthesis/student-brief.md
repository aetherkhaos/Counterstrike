# Framework-to-Tactical-Task Synthesis — Student Brief

## Objective

Map the adversary techniques and the paired response options you already built onto doctrinal tactical tasks.

## Context

Mission line for the worked example: deny or degrade collection from Network X in order to preserve friendly freedom of maneuver. Use the tactical-task lists, your Navigator layer, your D3FEND map, and your paired option sheet.

## Tasks

1. For each attack technique, name a tactical task.
2. For each D3FEND option, name a tactical task.
3. For each ENGAGE option, name a tactical task.
4. State goal, expected effect, and risk for each pair. Use probability and consequence. Do not mark every row extremely high.
5. Clean up earlier products: SALUTE, DRAW-D, OCOKA-W, exploitation plan, sub-technique choice, Navigator layer, and D3FEND graph.

## Deliverables / Evidence

One table the team can brief. Some tasks will not translate. Say so and say why.

## Constraints

A tool name is not a tactical task. A parent technique is not enough when the log supports a sub-technique.

## Success Criteria

The table uses doctrinal tasks, ties each option to a goal and a risk band, and the team can defend one row out loud.
